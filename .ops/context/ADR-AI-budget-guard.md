# ADR-AI-budget-guard

- Date: 2026-02-26
- Status: Accepted
- Deciders: Aiden (Director) + Product + Backend

## Context

项目预算约束已固定为月度上限 100 元（`budget.monthly_limit_cny=100`）。  
当前需要把预算策略从“被动告警”升级为“可执行门禁”：
- 超预算时优先降处理量，不牺牲结果质量基线；
- 保持 Notion 发布结构、错误码语义和回滚能力不变。

## Decision

1. 预算硬约束：
- 月预算上限固定为 `< 100 CNY`；
- 达到或超过上限后，进入预算保护态（Budget Guard Mode）。

2. 预算保护态原则：
- 保质量：维持主产出质量基线与发布结构，不降级内容字段完整性。
- 降处理量：通过限流、缩批、暂停低优先任务控制成本增长。

3. 降处理量优先级（必须按顺序执行）：
1. 先缩批：下调单次处理上限（抓取批次、发布批次）。
2. 再限频：延长调度间隔，暂停非关键定时任务。
3. 最后裁剪：仅在仍超预算时，关闭低价值附加流程（例如日报）。

4. 不允许动作：
- 不允许因预算直接改 IPC 契约或删除历史数据；
- 不允许在预算态下降低 Notion 发布字段完整性；
- 不允许用“静默失败”替代受控错误返回。

## Current Implementation Mapping (as-is)

1. 已落地：
- `BudgetStatus.limit_cny` 默认 100（`AppCore::default`）。
- IPC 已提供 `get_budget_status`，前端已展示预算占用。
- 当前熔断实现：
  - 使用率 >= 85%：`review_enabled=false`
  - 使用率 >= 95%：`daily_report_enabled=false`

2. 与本 ADR 的一致性判定：
- 一致：有预算上限、有熔断、有可观测预算占用。
- 不一致：当前熔断顺序为“先关复核，再关日报”，不满足“先降处理量、后裁剪质量相关环节”的优先级。

3. Gate B 强制实施项（本 ADR 的落地门槛）：
1. 将预算保护顺序改为“缩批 -> 限频 -> 关日报”，复核开关不得作为第一挡。
2. 把预算保护动作写入可观测日志（至少包含触发时刻、动作类型、触发阈值）。
3. 在系统健康页展示“当前预算保护挡位”与恢复条件。

## Executable Rules

1. 月预算阈值必须固定在配置与文档一致值：`100 CNY`。
2. 预算保护态下，发布与采集动作必须返回明确“已限流/已缩批”反馈，不得静默丢弃。
3. 预算保护态不得改动 `publish_approved_to_notion` 输出结构与 Notion 页面模板。
4. 预算恢复（低于阈值）后必须自动回到常态策略，并记录恢复时间。
5. 任意预算策略调整必须先写 `decision-log.md`，再改实现。

## Consequences

正向：
- 成本控制从“被动监控”升级为“主动门禁”；
- 预算波动不会直接破坏交付质量基线。

代价：
- 高峰期处理时延会增加，短期吞吐下降。

## Rollback

回滚触发条件（任一满足）：
1. 预算保护策略导致核心发布链路不可用；
2. 预算保护策略误杀高优先任务且 24 小时内无法修复。

回滚动作：
1. 暂时退回当前稳定熔断逻辑（保留日志）；
2. 在 `decision-log.md` 记录回滚范围、持续时间、恢复计划。
